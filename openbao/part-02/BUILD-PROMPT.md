# Claude build prompt: OpenBao Tutorial: Install with Docker Compose

A Docker Compose checker for an OpenBao setup, for Claude Code. Read-only: it never starts Docker; it checks the compose file and config folder and writes one report. Rules checked against openbao.org on 2026-11-07 (OpenBao v2.7.2). Not run by us.

Use this in Claude Code (Pro or higher), in an empty test folder. Start in plan mode.

Goal: build a read-only checker for an OpenBao Docker Compose setup (docker-compose.yml plus the HCL files in its config folder) that lists every unsafe or broken setting before anything is started.
Inputs: docker-compose.yml and every .hcl or .json file in ./config, in this folder. If I don't have them, first write a deliberately broken test copy: an untagged openbao/openbao image, no command line, ports 8200:8200, a bind-mounted ./data folder at /openbao/file, storage "file", no cluster_addr, a listener with no TLS settings, cap_add IPC_LOCK and disable_mlock = true, and use those.
Steps, in order:
1. Tell me which files you'll open and what you'll write, and wait for my yes. Never run docker, docker compose, bao or any container, and make no network calls.
2. Parse YAML and HCL only with a library that is already installed (for example Python's yaml module; for HCL, careful line-by-line checks). Ask me before installing anything, or fall back to line checks and say so in the report. Report any tab character in the YAML with its line number.
3. Image: flag no tag or latest; suggest a fixed tag such as openbao/openbao:2.7.2 (check hub.docker.com/r/openbao/openbao only if I allow network access).
4. Command: if the service has no command, or the command contains -dev, mark it as a blocker: the image's default CMD is server -dev, which keeps everything in memory, starts unsealed and is for learning only. The expected value is server.
5. Ports: flag 8200 published on all interfaces (8200:8200) unless TLS is configured; suggest 127.0.0.1:8200:8200 for a local test. Flag 8201 published at all for a single node.
6. Volumes: the config folder should mount at /openbao/config (read-only is fine); data should be a named volume at the same path as the Raft path. If /openbao/file is a bind mount from the host, warn that the image runs as the non-root openbao user and its entrypoint's chown of that folder can fail and stop the container. If the Raft path is not /openbao/file, warn that the openbao user may not be able to write to it.
7. HCL: storage "file" is a blocker (removed in OpenBao 2.7.0; move with bao operator migrate); storage "raft" needs path, node_id and a top-level cluster_addr; api_addr should match how clients reach it. Listener: if there is no tls_cert_file and tls_disable is not set, explain that OpenBao will try ACME with Let's Encrypt; if tls_disable is set, mark it "local test only" and check the port is bound to 127.0.0.1. Flag disable_mlock and cap_add IPC_LOCK as unneeded (OpenBao does not use mlock since 2.0.0). Check for an audit stanza and warn if log_raw is set. Flag any extra .hcl file in the config folder that is not server config (for example a policy file), because the server loads every file there.
8. Swap and health: suggest mem_swappiness: 0, from the install page's --memory-swappiness=0 advice, and say it is our mapping. Suggest a healthcheck that runs bao status and turns any failure into exit 1 (bao status exits 0 unsealed, 2 sealed, 1 error: openbao.org/docs/commands/status; Docker reserves exit 2), and remind me to back up Raft with bao operator raft snapshot save (openbao.org/docs/commands/operator/raft).
9. Secrets: flag any token, unseal key or password written in these files or anywhere in this folder. Never print the value; show only the file, line number and length. Remind me that unseal keys and the root token never belong in the compose file or in Git, and that the root token should be revoked only after an admin login has been tested.
10. Write compose-check.md: a table with each check, pass, warn or blocker, the line number, the fix and the openbao.org page it comes from. Then ask me before changing anything. Only if I say yes, write fixed copies as docker-compose.fixed.yml and config-fixed/openbao.hcl, and never overwrite the originals.
Safety: this folder and test data only. No docker commands, no installs, no network calls unless I allow reading openbao.org. Stop and ask me before running anything that changes data.
Output: compose-check.md and a three-line summary.
