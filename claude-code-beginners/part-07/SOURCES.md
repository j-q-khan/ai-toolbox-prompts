# Sources: Claude Code Setup: Permissions, Undo and CLAUDE.md, the Settings to Change First

Part 7 of the Claude Code for Beginners series. Checked 2026-11-13; nothing was installed or run.

- Permissions (2026-11-13): https://code.claude.com/docs/en/permissions "You can view and manage Claude Code's tool permissions with `/permissions`. The dialog lists all permission rules and the `settings.json` file each rule comes from."; "Allow rules let Claude Code use the specified tool without manual approval."; "Ask rules prompt for confirmation whenever Claude Code tries to use the specified tool."; "Deny rules prevent Claude Code from using the specified tool."; "Rules are evaluated in order: deny, then ask, then allow."; "Permission rules follow the format `Tool` or `Tool(specifier)`"; "`Read(./.env)` Matches reading the `.env` file in the current directory"; "Bare filenames follow gitignore semantics and match at any depth, so `Read(.env)` and `Read(**/.env)` are equivalent"; a deny `Read(.env)` blocks "any `.env` at or under the current directory"; "A `Read` deny rule also blocks the Edit and Write tools on the same path"; the warning that Read and Edit deny rules apply to built-in file tools and recognized file commands, not "arbitrary subprocesses … like a Python or Node script"; "Permission rules are enforced by Claude Code, not by the model. Instructions in your prompt or `CLAUDE.md` shape what Claude tries to do, but they don't change what Claude Code allows."; Bash commands need approval "except a built-in set of read-only commands", which "includes … read-only forms of `git`"; "Yes, and don't ask again" on a Bash command is "Permanently per repository and command" and saves the rule to `.claude/settings.local.json`; file modification approval "Until session end".
- Permission modes (2026-11-13): https://code.claude.com/docs/en/permission-modes status bar `⏸ manual mode on`; `~/.claude` is a protected path, "Prompted" in `default` mode, with the option "Yes, and allow Claude to edit files in its ~/.claude folder for this session".
- Settings (2026-11-13): https://code.claude.com/docs/en/settings "Installing Claude Code doesn't create any settings file."; "On Windows, `~/.claude` means `%USERPROFILE%\.claude`."
- Desktop (2026-11-13): https://code.claude.com/docs/en/desktop "Terminal-dialog commands: built-in commands that open an interactive panel in the terminal behave differently in the Code tab."; "Commands with no argument form, such as `/permissions`, reply with `isn't available in this environment`."; "Permission rules, allowed tools, and other settings in `settings.json` apply to Desktop sessions."; "Most Macs include Git by default. Run `git --version` in Terminal to check; if it prints a version number, Git is installed." The desktop and desktop-quickstart pages don't mention rewind, undo or checkpoints.
- Checkpointing (2026-11-13): https://code.claude.com/docs/en/checkpointing "Run `/rewind`, or press `Esc` twice when the prompt input is empty, to open the rewind menu."; "A file that only Bash commands changed isn't tracked and stays as it is. To revert it, use version control, such as Git."; subagent edits: "Claude Code usually doesn't capture those edits in your session's checkpoints"; "Manual changes you make to files outside of Claude Code and edits from other concurrent sessions are normally not captured"; snapshots deleted "by default about 30 days after the session last saved one"; "For permanent version history and collaboration, continue using version control, such as Git".
- Quickstart (2026-11-13): https://code.claude.com/docs/en/quickstart "Claude Code makes Git operations conversational", with the example "commit my changes with a descriptive message".
- Memory (2026-11-13): https://code.claude.com/docs/en/memory "CLAUDE.md files are markdown files that give Claude persistent instructions"; "Claude reads them at the start of every session"; "Run `/init` to generate a starting CLAUDE.md automatically … If a CLAUDE.md already exists, `/init` suggests improvements rather than overwriting it."; "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence."
- Data usage (2026-11-13): https://code.claude.com/docs/en/data-usage "Claude Code clients store session transcripts locally in plaintext under `~/.claude/projects/` for 30 days by default".
