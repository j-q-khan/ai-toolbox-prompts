# Claude build prompt: How to Get a Gemini API Key in Google AI Studio (and Keep It Safe)

Part 4 of the Google AI Studio series. Copy everything below the line into Claude Code.
What it builds follows Google's official Gemini API docs (checked 2026-11-13). Try it in a test folder first, and read every file it writes before you use it; it asks before it writes anything, and you run the install yourself.

---

Use this in Claude Code, in a new, empty test folder (never your home folder). Start in plan mode.

Goal: build a tiny Python app that tests my Gemini API key safely. It gets the key only from the GEMINI_API_KEY environment variable, and it refuses to start if it finds my key pasted into any file in this folder. Use a throwaway key with a spend cap and a billing alert, and dummy questions only.
Steps, in order:
1. Look up three Google pages and tell me what you find before you write anything: the model Google labels "Default general-purpose" on https://aistudio.google.com/docs/latest-model, the Python example for client.interactions.create on https://aistudio.google.com/docs/quickstart, and the environment variable and restriction advice on https://aistudio.google.com/docs/api-key. If any page has changed, tell me what changed, including anything it now says about what a key looks like.
2. Don't install anything yourself. Give me the exact commands to make a virtual environment in this test folder and install the only package, google-genai, with pip install -U google-genai, and I'll run them.
3. Write leak_scan.py: Google doesn't publish a key format, so don't guess one from a prefix. Instead, it takes the values of GEMINI_API_KEY and GOOGLE_API_KEY from the environment (skipping any that are unset or empty) and looks for those exact values in every text file in this folder and its subfolders, skipping the virtual environment folder, .git and files it can't decode as text. If it finds one, it prints the file name and line number only, never the value, and exits with an error. If neither variable is set, it says there's nothing to compare and exits with an error.
4. Write key_app.py: first it reads the key only from the environment variable GEMINI_API_KEY, and if that's missing it stops with a plain message telling me to set it in this terminal window or open a new window (Part 4 of the series shows how). Then it runs the scan from leak_scan.py, and if the scan finds my key in a file it stops with a plain message saying which file to clean and to treat that key as leaked (make a new one, then delete the old one on the Google Cloud website's Credentials page). It passes the key to the client explicitly (genai.Client(api_key=...)), so GOOGLE_API_KEY is never used by accident, and if GOOGLE_API_KEY is also set it prints a one-line note that Google's SDK would prefer that one. It never prints, logs or writes the key. It sends one dummy question to the default model from step 1 with client.interactions.create and prints interaction.output_text. If the request fails, it prints the error code and Google's message without the key, and reminds me that 401 means a missing, wrong or expired key, 403 a permission or billing problem, and 429 too many requests.
5. Write a .gitignore that covers .env, .env.* and the virtual environment folder.
6. Show me all three files and wait for my yes before saving them. I'll switch you out of plan mode so you can save.
7. Tell me to read every line before I run it, and remind me: restrict the key to the Gemini API on the keys page in Google AI Studio, and on the free tier Google may use what I send to improve its products and human reviewers may see it, so I should send dummy questions only, never personal or confidential information.
Safety: work only in this folder, never put a key in any file (the example key EXAMPLE-NOT-A-REAL-KEY is the only key text allowed), don't run the app yourself, and don't go online except to the three Google pages above.
Output: leak_scan.py, key_app.py, .gitignore, and a three-line summary of how to run it, including how to test the scan safely with the fake example key: set GEMINI_API_KEY to EXAMPLE-NOT-A-REAL-KEY in this window, put that text in a scratch file, run leak_scan.py, see it name the file, then delete the scratch file.
