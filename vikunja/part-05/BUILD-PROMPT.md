# Claude build prompt: Vikunja API Tutorial: Automate Your Tasks

An overdue-task API client for Claude Code. It lists your lists and overdue tasks with a look-only token, and only adds or ticks off a task, with a second token, after you type yes. Written from the vikunja.io API docs and the v2.8.0 code, checked 2026-11-06. Not run by us.

Use this in Claude Code (Pro or higher), in an empty test folder. Start in plan mode.

Goal: build a small Python client for Vikunja's v2 API that lists my overdue tasks, oldest first, and can add a task to one test list only when I confirm.
Inputs: a test Vikunja server (for example the Docker install from Part 2, version 2.8.0, with made-up tasks), its base URL in the environment variable VIKUNJA_URL (like http://localhost:3456), a look-only API token in VIKUNJA_TOKEN, and, for adding, a second token in VIKUNJA_WRITE_TOKEN. The look-only token is made under Settings, then API Tokens, with only Read All ticked under Tasks and under Projects, and a 30-day expiry; the second token has only Create and Update under Tasks. Never ask me to paste a token into the chat.
Steps, in order:
1. Show me the files you'll write and the commands you'll run, and wait for my yes. Use only Python's standard library (urllib, json, os), no installs.
2. Write vikunja_client.py with a function that sends requests with the header Authorization: Bearer plus the token from the environment, with a 30-second timeout, and stops with one plain sentence when either variable is missing, when the server can't be reached, or on a 401 (explain that Vikunja answers 401 for a wrong token, an expired token and a token missing that permission alike). Never print a token.
3. Add list_lists(): GET /api/v2/projects, returning id and title from the items field of the response envelope (treat a missing or null items field as an empty list), following total_pages if there is more than one page.
4. Add list_overdue(): GET /api/v2/tasks with the filter done = false && due_date before now, written with the less-than sign and URL-encoded in the code, plus sort_by=due_date and order_by=asc, following every page. Use snake_case field names, as Vikunja's filter docs do, and numeric label IDs if I ask for a label. Note in a comment that the API leaves out tasks with no due date unless filter_include_nulls=true.
5. Add a command-line entry: python vikunja_client.py overdue prints due date, list name and title, one task per line, then the total. python vikunja_client.py lists prints the lists.
6. Add add_task(list_id, title), sending POST /api/v2/projects/{id}/tasks with a JSON body containing only the title and VIKUNJA_WRITE_TOKEN, and done(task_id), sending PATCH /api/v2/tasks/{id} with only {"done": true}. Both must ask "Change this? (yes/no)" in the terminal before sending, and never use PUT, because on v2 a PUT replaces the whole task. Never send a test request to find out whether a token works. Don't run them yourself; tell me how.
7. Write a test file that runs list_overdue() against two fake pages saved in fixtures/ (no network), and run only that test.
8. Write README.md: how to make both tokens, how to set the variables in Git Bash or a macOS or Linux shell (from a private vikunja.env file) and in Windows PowerShell (typing each token at a hidden prompt, so it isn't saved in shell history), the four commands, how to run overdue every weekday at 8 with cron or Windows Task Scheduler, and how to switch to a bot user's token (Settings, then Bot Users, Create bot, share only the lists it should check with the bot, then make its token on the Bot Users page with the same boxes).
Safety: a test server with made-up data only, never real client data. Calls that only look come first. No calls to any server but VIKUNJA_URL. Stop and ask me before running anything that changes data.
Output: vikunja_client.py, the test, fixtures/, README.md, and a three-line summary.
