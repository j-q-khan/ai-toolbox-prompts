# Claude build prompt: Blender MCP with Claude, Part 2

Prepares a test folder for the official Blender Lab MCP (add-on and server both at version 1.0.3) with the locks from the video: a .claude/settings.json with ask rules, setup steps for your system, a code-review checklist, a server-disconnected troubleshooting page and a safety checklist. Claude installs and runs nothing; you run every command yourself. Written from the Blender Lab MCP source and setup wiki, the Blender 5.2 manual and Claude Code's docs, checked 2026-11-10. Not run by us.

Use this in Claude Code (Pro or higher), in a new, empty test folder. Start in plan mode.

Goal: prepare this folder for the official Blender Lab MCP (add-on and server both at version 1.0.3) with the locks from the video, and give me the steps and commands to run myself. You install nothing and run nothing.
Inputs: my operating system (ask me: Windows, macOS or Linux), and whether I already have uv and Git.
Steps, in order:
1. Tell me which files you'll create and wait for my yes. Only create files in this folder. Don't install, download or run anything, and make no web requests.
2. Write .claude/settings.json with exactly this permissions block: ask on mcp__blender__execute_blender_code, mcp__blender__execute_blender_code_for_cli, mcp__blender__render_viewport_to_path and mcp__blender__render_thumbnail_to_path. Show it to me.
3. Write setup-steps.md for my system: in Blender 5.2, download https://projects.blender.org/lab/blender_mcp/releases/download/v1.0.3/mcp-1.0.3.zip and keep it zipped; Edit, Preferences, Add-ons, the drop-down arrow at the top right, Install from Disk; check MCP is ticked in the Add-ons list; System, Network, tick Allow Online Access; in the MCP add-on's settings, untick Auto Start, leave Host and Port as they are, click Start MCP Bridge Server and check it says Server is running. Then the uv and Git install pages if I lack them, and a new terminal; git clone --depth 1 --branch v1.0.3 https://projects.blender.org/lab/blender_mcp.git into my home folder as blender_mcp; then, from this folder, claude mcp add --transport stdio blender -- uv --directory followed by the full path of blender_mcp/mcp in my home folder, then run blender-mcp; then claude mcp list, and the real test: in a new General file with the default cube deleted, ask Claude what's in the open file.
4. Write code-review.md: a checklist I go through before I say yes to any execute_blender_code call: only bpy and math imports; no os, subprocess, socket, urllib or requests; no file paths, open(), save, export or delete of files; no exec or eval of text from elsewhere; nothing I don't understand. If any line fails, I say no and ask why.
5. Write troubleshooting.md for "server disconnected": if claude mcp list says Failed to connect, the server didn't start (uv not found: open a new terminal; wrong folder: the path must end in blender_mcp/mcp; the very first start downloads helper libraries and can take longer than Claude Code waits, so wait and check again); if it says Connected but Claude can't connect to Blender, Blender isn't open or the add-on isn't running (Allow Online Access off, or the server not started in the add-on's settings).
6. Write safety-checklist.md: add-on from mcp-1.0.3.zip installed from disk; server cloned at tag v1.0.3; Host and Port left as they are; Auto Start off; Allow Online Access on only while I need it, because it covers every add-on; the settings file saved before starting Claude; a new file with nothing private open; I look over every script before saying yes; test models only, never a client's files; when finished, Stop MCP Server and untick Allow Online Access; when finished for good, claude mcp remove blender --scope local, remove the MCP add-on in Blender, and delete the blender_mcp folder. Then give me a three-line summary.
Safety: this folder only, test models only. You run nothing and install nothing; I run every command myself after reading it.
Output: .claude/settings.json, setup-steps.md, code-review.md, troubleshooting.md, safety-checklist.md and a three-line summary.
